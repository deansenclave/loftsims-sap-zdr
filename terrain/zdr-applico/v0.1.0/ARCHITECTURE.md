# ZDR Applico Terr-AI-n — Architecture v0.1.0

## Scope
Represent the independently developed ZDR Applico framework within the Terr-AI-n-based architecture, without replacing or modifying its Loft SimS implementation.

## Governance
#HumansOnTop applies to this Terr-AI-n and every sub-Terr-AI-n. Human decision-makers retain final authority over claims, determinations, configuration and deployment.

## Existing workflow (README-grounded)
Flavor-specific YAML → flavor checker → canonical AS-IS JSON → assessment JSON → FUTURE inputs → recommendations. Each data flow is assessed independently. Observed, contracted, asserted and proposed evidence must remain distinguishable.

## Components
- Flavor ingestion and normalization: recognized adapters and human-reviewed unknown templates.
- Assessment: retention, logging, model provider, training, deletion, backup and human access controls.
- Recommendations: future-state proposals do not change present-state determinations without verified implementation evidence.
- Evidence: source attribution, limitations, confidence and unresolved unknowns.
- Continuous assurance Sentinel: architectural target, not verified as implemented in the repository.

## Integration boundary
Terr-AI-nScape and Terr-AI-nium relationships are to be registered through explicit references. The exact parent Terr-AI-n and the Cookie Jar relationship are unresolved; no hierarchy is inferred.

## Release preservation
The repository README states published version folders are immutable. This registration lives under `terrain/zdr-applico/v0.1.0/` and does not edit any published application snapshot.
